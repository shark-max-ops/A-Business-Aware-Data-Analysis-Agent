# 分析使用说明（准备稿）

来源类型：project_policy。状态：draft。用途：说明当前功能、资料准备方式和下一阶段流程；不是官方手册或已完成产品功能清单。

## 当前已经可以使用

从根 README 按 Windows 命令启动后端和前端。在分析页的数据源抽屉查看已有真实数据快照、表结构、字段样本和质量报告。现有 CLI 可以导入 CSV、选择固定快照并执行受限只读 SQL；查询成功才保存 QueryArtifact。
数据与执行能力对应阶段 0—1；知识页仍是页面框架，不能通过当前页面上传这些材料、检索知识、生成 Wiki 或审核指标。

## 本次资料放在哪里

`data/knowledge_sources/` 是用户提供的官方原件；`data/knowledge_prepared/` 是 UTF-8 官方摘录、规范化代码表及本次校验结果；`knowledge_seed/project/` 是项目自己写的规则、限制与操作说明。
`knowledge_seed/manifest.json` 登记材料 ID、内容哈希、源文件哈希、URL、定位方式和已知适用期。原始下载时间未知就保持 null，不从文件修改时间推算。原件和本地数据产物被 Git 忽略，不能当作随仓库附带的公共数据。
`knowledge_seed/metrics.draft.json` 只是待导入的指标草稿，没有数据库修订 ID，不能直接宣称“已审核正式指标”。

## 阶段 2 实现后的目标流程（当前尚不能操作）

1. 将 manifest 指定的七份 Markdown 材料导入，保存不可变 DocumentRevision，并记录从整理原文到官方原件的定位。
2. 以中文别名搜索英文原文，检查摘录和出处；未配置 embedding 时如实显示文本检索模式。
3. 用真实输入文档生成 Wiki 草稿，保留引用；人工编辑与发布，重生成不得覆盖人工版本。
4. 将八个指标草稿绑定真实文档修订，审核分母、缺失处理与适用期后批准；有冲突先澄清。

这四步都是后续实施与验收目标。本次整理没有启动这些功能，也没有调用收费模型。

## 以后怎样读分析结论

先看数据月份和固定快照，再看采用哪个指标、分子/分母、缺失处理及规则版本。最后核对成功查询产物和来源摘录；来源存在并不自动证明解释正确。
“延误率”默认口径必须说明是项目有效到达口径；“原因构成”必须说明是已上报分钟构成。数据或口径不够明确时，系统应说明缺少什么，不给出看似完整的数字。
报表功能、数字点击取证和自然语言 Agent 分别在后续阶段实现，当前不能用这份手册代替运行验收。
