# 07 实施顺序、验收与评估

## 1. 总体方式

每阶段完成一个能运行的纵向路径，再进入下一阶段。开发 AI 每次先读契约和已有实现，避免一个会话生成后端、另一个会话重新发明不同字段。阶段之间更新根目录 `IMPLEMENTATION_STATUS.md`：已实现、未实现、实际执行的命令、检查结果、已知限制。

以下命令是目标接口，在对应阶段实现后运行。没有实现前，不把它们列成“已验证”。

规划更新：2026-11-05；6.A/6.B实施更新：2026-11-08；6.C—6.E按所列范围完成：2026-11-09。阶段0—5完成所列Windows工程验收，6.A核验原件、6.B多月快照、6.C范围与跨期口径已实现；失败和来源/语义边界见实施日志。6.D日期选择页面已接通；6.E有限真实路径已验收；下一步阶段7处理解释错位，阶段8处理上下文容量，阶段9工具能力扩展与阶段10整体评估仍待实施；不建设通用数据导入，目录整洁贯穿每次交付。

| 阶段 | 用户获得的能力 | 下一阶段入口 |
| --- | --- | --- |
| 4：持续调查 | 围绕已有数据积累发现与反证，继续追问并更新可追溯报告 | 能明确指出需要什么额外证据 |
| 5：外部核查 | 查询历史观测、检索并读取资料，将外部证据加入调查 | 工具与来源经过权限及引用校验 |
| 6：多月 BTS 数据与跨月调查 | 在固定多月快照中做日期范围调查、趋势和同口径比较 | 6.A—6.E按所列范围完成；复杂分组失败保留，下一步阶段7 |
| 7：解释错位优化 | 处理复杂分组结果中解释、标签与证据对应的问题 | 问题已记录，实施方案待定 |
| 8：上下文容量 | Run内压缩与同调查跨Run摘要 | 设计已补充，实现未开始，见根目录compact.md |
| 9：工具使用条件与分析扩展 | 按明确适用条件完成跨期、分布、分组、质量及外部证据核查 | 代表性问题有正确证据或准确限制，权限与预算不回退 |
| 10：整体评估与交付 | 获得可核对质量结果、失败分类和可复现演示 | 留出问题、真实路径与新环境验证，按实际范围交付 |

## 2. 阶段 0：建立可运行工程

交付：Python 包、FastAPI health、SQLite/Alembic、React 三页壳、统一 DTO/错误模型、配置、锁文件、gitignore、小型 fixture。

验收：`uv sync`、迁移、后端启动、`npm ci`、前端 build；缺少模型密钥仍可打开页面并看到未配置状态。根 README 给出 Windows PowerShell 启动命令。

可以交给 AI 的任务：

```text
只实现阶段 0。遵守 01 的目录和 06 的错误契约。
创建 health 与三个页面导航，建立 SQLite 迁移和配置。
使用明确 empty state，不以静态示例数据伪装真实后端结果。
运行基本启动检查和前端构建，更新 IMPLEMENTATION_STATUS.md。
```

## 3. 阶段 1：先完成数据库与受限查询

交付：fixture 导入、真实 BTS CSV 导入 CLI、manifest、数据质量报告、DataSnapshot、业务视图、SQL guard、子进程执行器、QueryArtifact。前端数据源抽屉可查看真实表结构；此时不必已有 LLM。

验收：真实 DuckDB 聚合返回已知结果；取消/备降/负延误/null/多条 SQL/外部读取/超时均有测试；未允许 SQL 不落到执行器；查询超时不留下子进程；换快照不覆盖旧文件。

目标：`uv run python -m metric_pilot.data.ingest --input ./data/bts/2026-01.csv --period 2026-01`。

## 4. 阶段 2：知识、Wiki 和指标

交付：Markdown/TXT 导入与版本、FTS5 + embedding、来源定位、Wiki 草稿/编辑/发布/回滚、结构化指标 v1。先使用 5—8 份精简材料，不做数百 PDF。

验收：能从中文问题找到相关英文术语来源；无效引用被拒绝；生成不会覆盖人工修改；生效期和冲突处理明确；旧 revision 可读。embedding 未配置时文本检索可单独用，但 UI 标记实际模式。

## 5. 阶段 3：Agent 与工具事件流

交付：LLM adapter、ToolRegistry、Runtime、上下文预算、错误恢复、Job/Run 状态、SSE 重放。先让 FakeLLM 完成真实的“指标 → 结构 → SQL”流程，再接真实模型。

验收：多工具调用消息配对；16 轮/24 调用/总 deadline 能终止；无效参数可反馈修复；重复失败有限；空结果正常；取消/重启/断线都有准确状态。

不把预置 SQL 直接按问题关键词命中作为 Agent 正常路径。指标 SQL 模板可以存在，但自由分析仍通过模型选工具与参数完成。

## 6. 阶段 4：在已有数据上完成持续调查

状态：报告与持续调查已实现，并完成 Windows、本地自动化及真实模型案例验收。真实案例包括结果驱动的后续核查、复用旧 ValueRef 的报告和利润缺数据澄清；基线同时核对发现与报告，逐日统计按日期与原 CSV 对齐。手机依据弹窗已核对实际视口与截图。历史失败记录保留，整体准确率与其他系统仍未评估。具体结果见 IMPLEMENTATION_STATUS.md。

目标：围绕一个业务目标持续核查，能从实际结果中选择下一步，并支持用户继续追问。本阶段使用已有数据、知识与安全 SQL；外部来源接入在阶段 5；后续阶段 6 扩充同一 BTS 口径的月份，不建设通用上传。

按顺序完成：

1. **保存调查目标和边界。** 创建调查记录，保存目标、范围、固定数据和知识快照、待核查问题、关联运行、预算与状态。关键条件不足才请求澄清；明确每次运行预算及调查累计预算，继续调查不能悄悄重置累计限制。
2. **按真实结果推进核查。** 把调查摘要与已执行检查交给现有 Agent 循环，模型选择知识、schema、SQL 和产物工具。检查比较人群、分母、样本量、缺失与其他解释，允许线索被否定、证据冲突或没有明显发现。保留简短行动说明，不保存内部思维链，不固定问题到 SQL 的路线。
3. **保存发现和证据。** 区分已核实事实、候选发现、矛盾证据、限制和建议；事实及数字绑定服务端验证的资料修订或成功查询产物，数字继续使用 ValueRef。候选解释不能在汇总时自动升级成事实。
4. **支持继续调查和报告修订。** 多个 Run 关联同一调查。先实现调查归属、同一数据与知识快照、成功状态、不可变产物的服务端校验，再允许跨 Run 引用；此前保持只引用本次 Run 的限制。数据、知识版本或关键范围变化须显式建立新调查或分支并记录关系，旧报告不重算。并行继续请求不得互相覆盖调查进展。
5. **完成中文调查界面。** 展示目标、当前行动、发现、依据、限制和可继续核查的问题；沿用简洁对话布局，工具记录按需展开。刷新可恢复；断线不取消，显式停止取消当前运行，已经保存的证据保留。

演示：用户问“本月哪些机场的到达延误值得优先关注？”先查适用口径与整体情况，再按实际结果核查日期、航线或 Reporting Carrier，并检查样本和分母。若出现日期集中现象，可提出天气核查需求，但当前数据不足时应明确停在证据边界。演示路线只用于验收，不写成生产代码的固定计划。项目指标仍须人工审核。

完成标准：至少展示一条由查询结果推动后续检查的真实模型调查，以及继续追问后更新发现和报告的路径；隔离验证线索被否定、无发现、缺口径或数据、失败、预算耗尽、取消和重放。验证跨调查、错版本、伪造 ID、失败或截断产物不能成为报告证据。人工核对结论与限制；自动引用校验不冒充语义或因果证明。

## 7. 阶段 5：接入外部来源与受控调查工具

状态：5.A—5.D 已完成 Windows 工程案例验收，可供用户试用；真实样本和未通过历史见实施记录，不代表整体语义准确率。不购买新数据服务，模型按实际用量计费。

目标：遇到航班数据解释不了的线索时，可以取得额外证据并核查。例如延误集中在特定日期后，查询对应机场附近的历史天气观测，或检索官方运行公告。外部来源只能增加可核对证据，不保证能找到原因。

### 三个工具及来源

| 独立工具（5.A/5.B 已实现） | 输入与用途 | 来源与返回内容 |
| --- | --- | --- |
| `query_historical_weather` | 机场、日期范围、需要的天气字段 | 近期调用 NOAA AWC 的 `/api/data/metar`，较早日期使用 NOAA/NCEI GHCNh 站点文件；返回实际观测、单位、站点、覆盖与缺失情况及固定来源引用 |
| `search_official_advisories` | 设施/机场、UTC 签发日期范围、公告类型 | 请求 FAA ATCSCC 的 `/adv/adv_list` 日期清单，在后端核对列表字段并筛选；返回编号、标题、设施、发布时间及服务端来源标识，不将列表摘要当成正文证据 |
| `read_external_source` | 上一步取得的 `source_ref`，以及必要的分页参数 | 后端读取已登记的 `/adv/adv_otherdis` 正文，返回公告原文、适用范围、时间与段落/行号定位；不接受模型提供的任意 URL |

天气工具须支持“昨天”这类近期日期，不能只覆盖演示月份。5.A 已实测 ATL/ORD/JFK 当地昨天的 AWC 观测、ATL 一月 GHCNh 样本，并登记官方使用条件；本地限制有隔离测试，不通过公共压力测试推定服务限流。AWC 当前官方 API 说明最近 30 天，项目保留边界余量；GHCNh 官方说明每日更新，不保证每站昨天数据完整。近期观测标记可能补报或修订；两个来源的字段与质量含义分别解释，不静默拼接成同一口径。官方入口：[AWC API](https://aviationweather.gov/data/api/)、[GHCNh](https://www.ncei.noaa.gov/products/global-historical-climatology-network-hourly)、[FAA 公告查询](https://www.fly.faa.gov/adv/advAdvisoryForm)。

公告范围先限定为 FAA ATCSCC 运行管制公告，不宣称覆盖全部 NOTAM、机场通知或航司声明。已有样本表明 FAA 类别筛选可能仍返回全部清单，因此须在后端筛选，再读取正文核对；不能依赖 HTTP 200 或同日标题认定相关。

### 实施步骤：5.A—5.D 分别验收

四步依次推进，每步在 IMPLEMENTATION_STATUS.md 单独记录交付、检查、未测项和下一入口；完成一个小步骤不代表整个阶段 5 完成。5.A/5.B 通过独立接口或命令验收，不需要模型；5.C 通过服务层与证据读取验收；5.D 再验收真实 Agent 与页面完整流程。共同安全规则从首次联网起落实，不能留到最后。

#### 5.A：来源基础与独立天气查询

当前：已实现并独立验收；使用方式、映射范围、网络选项与代码见 [5.A 讲解](../walkthroughs/stage-5a-weather.md)。没有接入分析对话或报告，不代表阶段 5 整体完成。

**交付：** 完成天气来源登记和 `query_historical_weather` 独立接口，覆盖近期 AWC 与较早 GHCNh。明确许可、认证、费用、访问限制及最小发送范围；未满足条件的来源不启用。建立有坐标、距离和依据的机场—气象站映射，处理多个候选、无站点和历史适用问题，不靠机场代码加前缀猜站点。补齐 Windows 时区数据，按机场当地日期解释“昨天”并转换为 UTC。输出原始质量码、单位、逐字段覆盖与缺失，检查重复/特殊报告和降水累计，不以零或预报补历史缺测。保存请求及原始响应、获取时间与哈希，供 5.C 接入证据链。

**独立验收：** 不调用模型，实际查询一个机场当地昨天，以及演示月份 2026 年 1 月的样本，能查看结果和出处；核对站点、单位、跨日/夏令时和字段覆盖。用可控用例验证无站点、歧义、缺测、限量、超时、真实请求取消和危险地址拒绝。每个启用来源须有使用条件记录，文档承诺不能代替真实请求。完成后可以独立查天气，但尚不能据此宣称报告已支持外部证据。

#### 5.B：独立公告检索与正文读取

当前：已实现并独立验收；实际 DFW 正例、仅 AAL 限制、管制取消、拟议、无匹配与不相关火山反例、固定正文分页和实际 HTTPS 取消均有记录。入口、来源使用边界与代码见 [5.B 讲解](../walkthroughs/stage-5b-advisories.md)。不接受任意 URL；通用抓取许可证及数字配额仍未知，当前限定本机低频查阅，不作批量再分发授权。后续 5.C/5.D 的证据、Agent 与页面接入也已完成，本节只描述独立工具范围。

**依赖与交付：** 复用 5.A 的受控 HTTP 基础，单独确认 FAA 使用条件；FAA 尚未满足启用条件不撤销已通过的天气验收。完成 `search_official_advisories` 和 `read_external_source` 独立接口。按日期取得清单，后端筛选机场/设施和类型，从实际链接登记 `source_ref`；读取仅接受服务端标识，不接受任意 URL。HTML 解析提取标题、MESSAGE、有效时间和签发时间，去除导航、保留原文及换行，支持分页和定位。核对编号、日期、发布/更新/延长/取消管制及航司范围，不确定信息明确标记；原件、请求和哈希留存复用 5.A 机制。

**独立验收：** 不调用模型，跑通“机场和日期→候选清单→选定正文→查看原文”，正例与不相关反例均可核对。覆盖仅限某航司、管制取消/更新、无结果、错误页、结构变化、伪造来源标识、跳转越界及取消。验证本地筛选，不依赖 FAA 失效的类别过滤；正文失败不得使用摘要替代。此时三个工具可独立使用，尚未开放给 Agent。

#### 5.C：外部证据冻结与报告取值

当前：已实现并独立验收。服务端复核原件后登记外部证据，天气经独立固定表与原有安全 SQL 生成成功产物，再由 ValueRef 取值；主数据快照检查保留。运行固定来源条件下的外部版本，跨运行复用须符合阶段 4 成功旧运行授权。实际 ATL 一月天气与 FAA #049 正文已生成隔离报告并逐值核对，未调用模型或执行 BTS SQL，不算 5.D。代码、命令与限制见 [5.C 讲解](../walkthroughs/stage-5c-external-evidence.md)。

**依赖与交付：** 基于 5.A/5.B 的真实留存响应，接入不可变外部证据登记、读取及报告验证。服务端分配证据 ID，保存 URL/条件、发布与生效时间（未知则标记）、获取时间、哈希和正文定位；重新获取追加版本。天气计算形成允许查询的固定数据快照，经成功 SQL 生成 QueryArtifact，再供 ValueRef 取值。显式扩展运行/调查对外部快照和证据的归属、版本及权限校验，不简单放宽主快照检查。公告必须引用实际读取的固定正文，检索候选不自动成为已核实证据。

**独立验收：** 不要求模型选工具，通过服务层创建带天气数字和公告正文引用的报告样本，逐项核对 ValueRef 与原文位置。拒绝跨调查、错版本、伪造 ID、失败/截断产物和篡改文件；验证重新获取后旧证据、旧报告不变。沿用阶段 4 已授权的同调查成功旧运行复用规则，并核对外部版本绑定，不扩大为任意跨运行引用。完成后证据和报告能力可验收，Agent 自动外部核查仍留在 5.D。

#### 5.D：调查循环、页面与完整路径

最新状态（2026-11-04）：新调查与同调查续查已通过所列路径及数值/范围抽样复核，保留语义备注和失败历史；完整检查及边界见 IMPLEMENTATION_STATUS.md 中相关事项的最新日期记录。

当前：已实现并完成所列 Windows 工程案例验收。工具自动固定证据，天气数字经安全查询供 ValueRef；本轮候选与同调查成功来源显式授权，联网共享额度、取消实际请求并留收尾时间。公告多日部分失败保留已核对日期并标缺口，完整原文留存、模型只接有限节选，页面共用天气覆盖卡和带行号公告正文。最新新调查及同调查续查分别逐项核对 45、32 个引用值，保留人工复核备注；历史天气本次复用经哈希校验的短期原件，不称为重新下载。先前三项模型案例仅保留自动路径检查含义，不能代替语义验收；昨日真实 AWC 读取、正式适配器 HTTPS 正文到达后取消、桌面和 390px 手机另有记录。模型解释与发现分类仍需人工判断，不代表整体准确率。代码、启动与限制见 [5.D 讲解](../walkthroughs/stage-5d-investigation-tools.md)。

**依赖与交付：** 在 5.A—5.C 通过后，三个工具接入现有 ToolRegistry、参数校验、消息配对、审计、显式取消、SSE 与预算；模型根据实际结果决定是否查天气、找公告和读正文，不写死题目路线。保存支持证据、反证和限制；外部失败不阻断仍可独立完成的本地核查。页面沿用简短行动与按需展开的详情，在发现、报告和依据抽屉中区分本地统计、外部观测、官方公告及模型解释，展示覆盖、时间、来源和原文定位，长文及技术记录按需展开。

**完整验收：** 真实模型完成“本地异常→外部查询与相关正文→固定证据→发现与 ValueRef 报告→继续调查”。核对工具配对、预算收尾、提示注入防护、显式取消、断线重放和旧证据复用；无相关资料也应如实收尾，本地调查可独立使用。桌面与手机检查中文、长文、依据弹窗及失败/空态并查看截图。接口、证据与真实完整路径分别留记录；5.D 通过后，才能将阶段 5 整体记为完成。

### 共同使用规则与验收

优先使用直接 HTTP 适配，不强制部署 MCP；以后采用 MCP 也须经过同一服务端约束。仅允许登记的只读工具、HTTPS 来源和请求参数；限制地点、日期跨度、请求次数、响应/解压后大小、重试和总时间，检查实际连接地址及每次跳转，阻止本机、内网和未允许目的地。取消须停止实际请求/读取，不能只停止页面等待。外部正文属于不可信输入，不执行其中脚本或指令，不允许其改变权限；完整原文留存不等于无限塞入模型上下文，要给收尾保留预算。

没有匹配公告不等于事件没有发生；天气与异常同时出现不等于因果。公告描述、预期影响与 BTS 实际统计分别标记，不将公告中的预计延误当作实际航班结果。查到昨天的天气也不代表现有一月航班快照支持分析昨天的航班，比较必须核对地点、时间和人群范围。

完成标准：三个工具先独立跑通，再演示“本地异常→天气/相关公告正文→固定证据→发现与 ValueRef 报告→继续调查”的真实模型路径。近期路径实测机场当地昨天，历史路径覆盖演示月份，分别核对字段覆盖与限制，不承诺全部机场完整。覆盖无数据、缺测、冲突、重复、错误页、结构变化、限流、认证失败、超时、真实取消、危险 URL/跳转、提示注入、站点/时区不匹配、证据越权和旧版本重放。来源变动不改变旧报告，未启用或未配置时如实显示，本地调查仍可独立使用；接口样本成功、本地模拟和真实完整链路分别记录，未运行的不计通过。

3. **记录失败与实际消耗。** 保留检索、SQL、模型、口径、来源、预算、取消和界面失败；报告真实耗时、请求与用量，费用以可核实账单/计价为准。未测范围明确说明，不预填提升比例，不把复跑单项算成全库全绿。
4. **交付可复现演示。** 按 README 从新环境安装、迁移和准备 BTS 数据，展示多月调查、条件化工具、追问、失败/取消/重放和版本更新后旧报告不变；保留来源许可、依赖锁和桌面/手机说明。Windows 与其他系统分别记录实际验证范围。

完成标准：真实 BTS 多月调查与工具扩展均有独立核对和有限语义复核；评估有未参与调参的问题及失败分类，可复现演示所需目录与命令清楚，未实现/未验证内容如实保留。通用 CSV/XLSX 上传、任意业务表语义映射和数据库连接不属于本轮交付范围。

### 贯穿阶段 6—10：保持文件与目录整洁

复用 `backend/src/metric_pilot/` 既有职责目录、`frontend/src/`、`scripts/`、`docs/` 与本蓝图；不为每个问题、月份或测试轮次新增顶层目录/独立工具。只有明确新职责才拆模块，不为减少文件数将不同职责塞进大文件。

原始月份集中 `data/bts/`，知识原件与整理材料沿用 `data/knowledge_sources/`、`data/knowledge_prepared/`；不可变运行数据与正式验收记录保留在 `storage/`，可再生成缓存与临时诊断统一在忽略目录。重复脚本优先整理为现有命令的显式参数，完成后清理一次性产物；清理不删除旧报告、失败记录、授权和来源原件。

每次交付同步当前入口、文档、DTO 和路径；历史实施日志及归档保留当时事实，不批量改写旧验收。整理时先核对引用、哈希和用途，再移动/删除；真实数据、密钥及大产物不提交 Git。

## 13. 评估集设计

建议 40 个标准问题：10 个基础查询、10 个口径敏感问题、8 个组合分析、6 个无法回答/需澄清问题、6 个恢复与边界问题。另建 SQL 防护与证据完整性测试，不与问答分数混为一谈。

从中划分开发集和未参与调参的测试集；即使规模小也记录划分，不拿反复调试的同一批问题声称泛化结果。

每道题包含：

```yaml
id: arrival_deviation_vs_delay_01
question: 比较本月各航空公司的平均到达偏差与平均非负延误
snapshot_manifest: 实际固定清单路径
knowledge_snapshot: 实际固定知识版本清单
expected_metric_keys:
  - mean_arrival_deviation
  - mean_nonnegative_delay
required_sources:
  - 实际指标定义修订ID
gold_sql_file: gold/arrival_deviation_vs_delay_01.sql
checks:
  - same_population
  - numeric_tolerance
  - evidence_resolves
expected_behavior: answer
```

Gold SQL 由开发者结合指标定义审阅，再在固定快照执行。不能用被评估 Agent 生成的答案直接当 gold。数值比较先按业务键对齐，再按类型设容差；没有 ORDER BY 的结果不按偶然行顺序判错。空值和零分开。

## 14. 对照实验

在同一模型、同一快照、相近工具预算下比较：

| 配置 | 目的 |
| --- | --- |
| A：仅 schema + SQL 工具 | 测量不带业务知识的基础能力 |
| B：A + 原文检索 | 测量业务资料检索的收益 |
| C：B + Wiki 与结构化指标 | 测量知识整理和指标约束的收益 |

执行恢复可另做开启/关闭的独立实验，避免多项同时改变后无法解释原因。固定模型参数和 provider 版本信息；服务端不支持 seed 时如实记录。真实运行至少保留逐题记录，有成本允许时重复运行观察波动。

指标建议：

- 查询可执行率：合法问题中产生成功查询的比例。
- 数值正确率：结果与 gold 按键对齐后的正确率。
- 口径遵守率：使用正确人群、分母、阈值和时间范围的比例。
- 引用完整率：可解析引用覆盖应有依据的结构化结论的比例。
- 来源支持率：抽样人工判断引用是否真正支持解释，区别于 ID 存在。
- 外部证据匹配：人工核对地点、日期、时区、观测或公告适用范围与正文是否支持结论；分别记录检索命中、原文取得、无覆盖及冲突，不把搜到链接算成核查成功。
- 调查质量：人工核对是否选择合理的后续检查、处理样本与口径、呈现反证、控制无依据因果结论，以及对无发现和数据不足的处理；逐例记录而不以单一分数冒充语义证明。
- 正确澄清/拒答率：对材料不足或歧义问题的预期行为。
- 延迟、调用次数、token 和估算费用；费用按实际 provider 计价，不硬编码未核实价格。

Wiki 不一定提升每道题。若 C 不如 B，分析错误来源，如摘要丢失范围、检索偏向生成文本、规则版本错误；不要为了简历删除失败样例。

## 15. 关键小型 fixture

至少覆盖：提前到达、恰好 15 分钟、14 分钟、正常 0 分钟、取消、备降、缺失 arrival_delay、null 原因分钟、零分母、机场维表重复键候选、两个不同航空公司、至少两个日期。

用人工可算的小数据给出 gold。例如 3 个 eligible arrivals 的 arrival_delay 为 -10、0、20，则平均偏差为 10/3，非负平均为 20/3，延误率为 1/3。加入取消记录后，eligible 分母不变，计划航班与取消率分母变化。
