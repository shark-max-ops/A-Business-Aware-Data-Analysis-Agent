# 0003：固定知识修订、引用与审核边界

日期：2026-10-30。范围：蓝图 04 / 06 / 07 的阶段 2；阶段 3 的分析 Agent 和 SSE 不在本次实现范围。

## 参考与取舍

参考包内 DB-GPT Wiki pipeline 的来源绑定、去重与草稿修订，以及 Wiki models 的 expected_version 乐观锁；未导入或依赖 DB-GPT 代码。首版是单个串行知识 worker、最多 40 个平面 Wiki 页面，不复制平台级 taxonomy、图谱和并行流水线。
文档按标题/段落提取来源片段，同文本哈希去重后合并生成一个明确目标页面；不是自动从所有资料生成整个知识站。输入超过 48k 文本字符明确拒绝，模型候选最多一次引用修正；版本冲突不以覆盖来修复。

## 文档与原文权威

SQLite 保存完整 UTF-8 原文、内容哈希和不可变 DocumentRevision；更新只改文档指针并追加修订。分块保留原文字符范围、行号、标题与整理材料中已有的 source locator，长段落分片并重叠 200 字符。
原件已在准备期保留哈希/URL/页码；服务首版只接收 Markdown/TXT，不能宣称在线可靠解析了所有 PDF 表格。
种子官方材料显式启用项目注释分离：其中中文提示、映射与项目章节的片段标为 project_policy，原文英文条目保留 official_reference；普通用户文档不套用这个特定整理包的规则。页面分别显示来源类型。

## 检索与冻结范围

FTS5 保存英文词及显式中文单字/双字词；维护少量中英领域别名，让中文问题可命中官方英文术语。它不是自然语言问题到 SQL 的路由，也没有冒充 Agent。
原文向量以模型/规范化端点键、维度、文本哈希、BLOB 保存，读取时校验维度和哈希，使用余弦距离；关键词和向量候选用 k=60 的 RRF 合并，不把不同量纲原始分数相加。k=60 是初始设计值，不声称最优。
已发布 Wiki 另作关键词导航；其引用可以继续打开原始片段。当前未对 Wiki 正文单独做向量索引，界面明确标为关键词导航。
知识快照由服务器固定当前文档、发布 Wiki、活动已审核指标及其依赖的旧原文修订。搜索只访问该清单；指定数据日期时过滤明确不适用资料，未知历史生效期给出限制，不虚构截止日期。

## 引用与发布

引用必须属于本次输入修订，片段存在，text_hash 匹配，excerpt 实际包含在原文中；正文各段需要引用标记。检查无法自动证明段落解释语义正确，发布前仍须人工核对。
模型只生成最终文本草稿，没有写数据库、发布 Wiki 或批准指标的工具。Wiki 正文通过受限 Markdown 渲染，不执行模型 HTML/JS，不加载模型图片；链接仅允许 HTTP(S) 或页内引用。人工创建也要经过相同引用验证。
草稿编辑、发布和回滚均追加不可变修订。发布指针单独维护；回滚只创建草稿，不删除历史或自动替换发布指针。前端编辑保留载入时版本，不能用刷新后的新版本号掩盖旧编辑内容。

## 指标

MetricDefinition 与蓝图字段同步，首批八项均为 project_policy。创建/编辑只能保存草稿，独立审核操作创建 approved 修订。当前已审核指针代表该指标在新快照中的活动版本，旧快照继续固定旧版本。
resolve 只接受该快照中已审核、日期匹配的定义，无候选或多候选分别返回不适用/冲突，不拼接规则。不声称能自动发现自由文本中的所有业务矛盾。
首版不支持自由公式成为 official_mapping，也没有实现 template_key 对应的可执行 SQL 构建器；公式字符串不 eval。Agent 与后续报告只能按相应阶段实现后再声明口径验证能力。

## 模型与任务

一个 HTTP 适配入口分别调用已配置的 embedding 与 Chat Completions。根 URL/完整 embedding 端点规范化，不覆盖用户密钥；JSON 输出及 reasoning_effort 参数在当前服务实际验证。
参考 [DeepSeek JSON 输出](https://api-docs.deepseek.com/guides/json_mode/) 与 [Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/) 的参数说明；参数不是所有兼容服务都支持，其他服务需按实际能力配置。健康检查不执行付费探测。
任务、固定输入、结果和失败历史持久化。领取和版本写入短事务串行化，模型网络调用不持有写事务；重启将遗留 running 标为中断失败，显式重试不伪称恢复模型内部状态。部署边界仍是单 API 进程/单知识 worker。
只记录最终候选与白名单数值用量，不保存 reasoning_content。计费取实际服务账单，本次没有估算总费用或声称问答准确率提升。

## 验证

真实 SQLite/FTS5、模型隔离向量持久化、中文查英文、修订不漂移、跨输入/伪造引用拒绝、乐观锁、回滚、审核及生效期均有测试；测试模型只在 backend/tests 中替换 HTTP，不进入正式配置路径。
真实材料与远程模型结果在忽略的 storage/validation 中，失败尝试不伪装成功。独立浏览器验收使用合成说明和专用 SQLite，操作发布/审核不批准用户的八项正式项目规则。实际检查结果以 IMPLEMENTATION_STATUS.md 为准。

## 用户试用反馈后的范围调整（2026-10-30）

用户明确要求关系图与易读的指标页面，因此在既有 Wiki 内增加引用关系导航；原先不做图的首版取舍以本节为准。文档修订 → 实际引用主题 → Wiki，以及文档修订 → 指标，均来自已保存记录；不从模型文字猜测因果、自动分类或企业制度。图包含草稿并标出状态，按指标修订变化刷新；没有新增站点路由或图数据库。

检索索引加入原有章节标题，中文术语同时用于关键词与向量查询；字段解释问题优先直接定义，分母/计算问题仍保留项目口径。重排、同修订同章节去重和无正文片段过滤仅影响候选展示，不修改资料权威或内容。摘录为原文连续子串，默认最多 320 字符；短表格最多 900 字符完整展示，长文可展开。FTS 派生索引可重建，旧片段 ID、正文、哈希、引用和知识快照保持可回查。

Markdown 表格、编号引用、关系图与指标阅读卡片替代默认原文/ID/编辑表单展示。技术 ID 和原始计算字段仍可按需展开；字段标签只作显示转换，不变更计算规则、审核状态和生效期。表格末行的引用在显示时独立成段，避免被 Markdown 丢弃为多余单元格，存储正文保持原样。
