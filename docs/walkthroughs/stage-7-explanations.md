# 阶段7：分组身份、展示范围与真实解释核查

## 阶段目标

解决复杂分组中“引用真实、解释却错位”的问题。服务端只验证能够确定的结构和冻结取值，模型解释仍须结合来源复核。真实数据、运行、失败报告和本机验收结果保存在忽略的 `storage/validation/stage7/`，不随源码分发。

## 执行流程

1. 安全查询生成成功冻结产物。模型看到的预览和结果页同时给出 `row_indices`，明确每行的绝对零基行号；分页或上下文节选不会将页内位置当作引用行号。
2. 文字中的月份、航司和数量通过 ValueRef 引用。`row_bindings` 把维度键和数量键组成同行陈述。不同组即使月份文字相同，也须各自引用对应行的月份单元格。
3. 表图完整展示引用产物。可选 `display_scope` 声明可见维度、分类人群和日粒度子范围；指定人群先查询筛选产物，标题不能筛行。主范围由服务端固定，子范围独立显示。
4. 图表横轴重复时拒绝。跨月、跨航司的分类须在查询中完整表达，不能由物化层静默合计、筛选或重排。
5. 报告与发现使用同一物化校验。绑定错键、错行的安全详情返回模型，指出可用占位键或各键引用位置。候选修正预算、重复失败停止、工具权限与旧证据授权保持原边界。
6. 成功报告不可变冻结。旧格式缺少新字段仍可读取；读取不重新生成内容或改变哈希。自然语言标题、遗漏声明、分母含义及因果解释不自动成为“已验证语义”。

## 具体例子与反例基线

以下是真实6.E拒绝记录的索引，不把合成测试当作这些记录的重新模型验收。原JSON、旧运行与报告不覆盖；本机复验另存 `rejected-baseline.json`，绑定原文件哈希。

| 类别 | 原记录（6.E验收目录内） | 本阶段处理与边界 |
| --- | --- | --- |
| 航司标签与行错位 | `monthly-attempt-10.json`、`followup-attempt-2.json` | 明确绝对行号，引用月份与航司并同行绑定；手写身份仍须语义复核 |
| 表格人群与标题不符 | `followup-attempt-2.json` | 声明人群时逐行核对，先生成筛选产物；不解析自由标题 |
| 跨月横轴丢失时间 | `followup-attempt-2.json` | 当前物化路径对原歧义图表返回 `REPORT_CHART_AXIS_AMBIGUOUS` |
| 结束日文字与固定范围不符 | `monthly-attempt-2.json` | 结构化主范围须匹配服务端范围，页面独立显示；自由文字仍需复核 |
| 无冻结合计的数量叙述 | `monthly-attempt-4.json` | 合计、差值和近似区间先查询；不宣称可自动识别所有无依据文字数字 |

例如，同月两家航司各有一行，不能把第一行的月份引用同时用于第二行绑定，即使显示文字相同；第二行应有自己的月份键。错行反馈返回各键位置，模型可在原权限下修正。不能删除绑定来掩盖不符，也不能换成无关产物。

## 验证与限制

后续关系结论修复：新报告只把服务端RankingBlock/ComparisonBlock计算出的关系作为已核对结论。模型提交比较集合、列与必要行选择，不填写赢家、名次或升降；完整结果集、唯一身份、并列、缺测与方向均有证明。普通模板即使引用真实数字也保留为未核实解释，默认折叠，不与结论混排；服务端生成的观察块仅核对取值。实际新模型已经生成无需人工修订的前三组/最低组和两项OH跨月关系；原报告不改写。完整边界见[报告契约](../design/05-evidence-and-reports.md#11-已核对关系与未核实解释2026-11-14)。

[范围测试](../../backend/tests/test_report_scopes.py)、[同行测试](../../backend/tests/test_report_row_bindings.py)、[分页与反馈测试](../../backend/tests/test_history_context.py)使用明确合成数据和真实受控查询。独立验收器测试拒绝错误分母、身份、缺组及未审核口径；数值通过不会自动设置语义接受。

真实验收通过显式选择的案例逐次调用已配置模型，另从原CSV按日×航司计数建立基线，核对月度、完整航司×月份、指定航司旧证据续查及日粒度分支。语义复核与成功/拒绝单独记录，真实页面只读检查不产生新模型请求。实际结果、运行配置和尚未覆盖项以[实施日志](../../IMPLEMENTATION_STATUS.md)为准。

本阶段没有实现阶段8的摘要机制，没有扩大工具权限或静默提高项目默认上下文。真实模型仍可能给出错标或无依据的文字；有限案例通过不代表整体准确率或稳定成功率。

## 试用失败与重复调用修复

后续“保存发现”反复失败修复：当前模型只提交`observations: [{artifact_id, row, columns}]`，至多四行且每行六列。服务端按真实数据逐行生成占位符、ValueRef和同行绑定，并返回可复用的report_block；跨月两行各自绑定，不要求两个月份同行。由此避免模型先修模板键、再修绑定键、再错误拼接跨月记录。原24引用上限、授权、哈希、范围、指标和旧格式严格校验保留；无数据可用时可用note保存明确标记的待复核限制。新输入是对保存契约的简化，不预置任何问题对应的SQL或分析答案。真实验收只确认保存和冻结取值；额外叙述、排序与因果仍单独复核。

用户按月份与航司续查时，候选发现一次提交30个引用超过24上限，反复重试后整次失败。现在错误返回实际数量与允许上限；已有成功发现时，连续两次可选记录校验失败会关闭工具并保留明确标记的部分结果。没有成功发现或发生权限、口径、范围错误时，仍按原边界拒绝。

模型启动上下文提供固定字段、最多六个已授权成功旧产物的元数据索引，以及其中仍覆盖当前固定范围的已审核口径；用户主动选择与服务端核验缓存分别标记，不自动审批指标。读取数值仍走原授权和哈希校验。模型可见的表格行使用 `indexed_rows: [[绝对行号, 列值数组], ...]`，直接把行号贴近实际值；API和审计中的原始行保持原样。

同一批已读证据最多保存两条发现后收尾；新的实际行或查询证据重置计数，重复读取旧行不能重置。报告结构的既有两次修正预算耗尽后，只对展示类错误允许保留完整成功表格，服务端冻结 `partial=true` 和不可通过修改说明移除的限制；界面明确显示“部分完成”。不新增查询、不截列或重新计算，不把失败工具当作证据。

真实复测的最新原问题运行从11次工具/3次失败降为4次工具/0次失败，但模型仍误判最低组。独立CSV核对后另建人工报告修订，不把它计作模型语义通过；旧失败、原报告和错误发现仍保留。完整结果及限制见实施日志，阶段8仍未实施。
