# 阶段 5.D：在调查中自动核查天气和运行公告

当前状态（2026-11-04）：5.D 完成所列 Windows 工程案例验收，可供用户试用；自动引用检查不等于语义验收，历史错误报告及复核备注保留。详见 IMPLEMENTATION_STATUS.md 末尾。

这一小步把 5.A—5.C 的独立工具与证据服务接入分析对话。用户提出调查目标，模型根据实际数据决定是否补查天气、寻找公告、读取正文，再保存发现与限制、生成报告，并在下一轮继续核对。

## 一次调查怎样执行

```text
用户提出调查目标
  → Agent 查航班记录、核对范围
  → 根据实际结果选择天气或公告核查
  → 服务端限制来源、次数、字节和时间；保留原件
  → 自动固定外部版本；天气数字经安全 SQL 形成成功产物
  → 保存发现、反证或限制；报告通过 ValueRef 取值并引用固定正文
  → 页面查看依据，或继续同一调查复用成功旧证据
```

天气同现、公告上报条件或预计延误都不能直接证明航班异常原因。公告的 UTC 签发日、原文有效期及天气机场当地日分别核对；只有 DAL 等指定航司适用的通知不能推广到全部航司。

## 1. 三个工具怎样进入模型循环

[agent/tools.py](../../backend/src/metric_pilot/agent/tools.py) 注册 `query_historical_weather`、`search_official_advisories`、`read_external_source`，公开严格签名；天气字段使用枚举，模型不能猜 URL、路径或数据库权限。[external_tools.py](../../backend/src/metric_pilot/agent/external_tools.py) 组合已有来源适配和 5.C 的证据服务，不加载通用网页抓取器或任意 MCP。

天气成功后自动复核原件、登记固定证据，并返回外部快照、实际字段和覆盖。`query_sql` 明确选择该外部快照、探索用途及范围后查询，复用原有 AST、只读子进程、超时和取消，不能跨库把天气与航班表混接。

公告检索返回候选；`read_external_source` 才读取并固定正文。只接受本轮登记候选或授权的同调查旧证据 ID，知道别的调查的正文编号也不能读取。首次最多返回五个候选；通过固定清单 `search_ref` 翻页，正文通过固定 `evidence_id` 和行偏移翻页，不重抓正文。

多日检索遇到后续某日无法核对时，保留先前完整核对日期的候选，显式标 `partial`、失败及未请求日期，并停止后续请求；第一日即失败仍返回失败。部分清单不是完整空结果，模型和页面都会看到缺口。

## 2. 限制预算，真正停止外部读取

[settings.py](../../backend/src/metric_pilot/settings.py) 提供来源配置；[agent/api.py](../../backend/src/metric_pilot/agent/api.py) 在运行创建时固定外部额度。默认每运行最多 8 次实际请求、80 MiB 响应读取量及最多 120 秒外部时间，同时受原 180 秒运行总期限控制。每次操作至少给收尾留下 25 秒，不给每个工具重新分配一整份额度；请求间隔沿用来源客户端的两秒限制。

[runtime.py](../../backend/src/metric_pilot/agent/runtime.py) 让外部 HTTP 在实际异步任务中执行。点击停止会取消并等待请求退出、关闭流和连接池；整批模型工具调用继续补齐对应结果与持久化事件。关闭页面只断开订阅，SSE 序号和重放沿用已有实现。

相同成功请求在本轮复用同一结果，相同失败不会重新联网；来源失败不会直接中断仍可完成的本地核查。所有请求继续执行原有 HTTPS、允许来源、公开 IP/TLS、跳转拒绝和响应上限规则，不购买新数据服务、不绕过来源封锁。

`EXTERNAL_DNS_MODE` 默认 `system`。本机虚拟 DNS 会返回不允许的地址时，可以由操作者在 `.env` 明确选择 `cloudflare`，只向固定加密 DNS 发送允许来源域名；不发送提问、航班结果或密钥，也不自动切换。当前本机已配置这一选项。

## 3. 如何让模型用得下这些资料

[context.py](../../backend/src/metric_pilot/agent/context.py) 保留目标、权限、版本和完整工具消息配对，裁剪展示副本。模型工具签名不重复携带类文档注释；调查报告契约仅描述一份，执行约束与字段验证继续保留。

天气长采样和公告长文不直接堆进上下文；正文节选明确标记，并给出继续读取的偏移。原始工具审计和完整证据不改。小型已授权旧查询也缓存真实结果及完整性标记，避免下一轮因为摘要被裁剪而反复读取。同一调查旧天气版本必须显式选定后才能执行新的天气 SQL；来源和查询归属仍由服务端检查。

## 4. 发现、报告和页面怎样衔接

`record_finding` 使用报告同一条取值与引用校验路径，并将实际外部快照冻结进发现。可以保存观察事实、候选解释、反证、限制或建议；数字来自成功产物的 ValueRef。报告与旧版本不随来源更新重算。

[ExternalSource.tsx](../../frontend/src/components/ExternalSource.tsx) 在发现弹窗和报告依据抽屉中共用：天气卡显示站点、时区、UTC 窗口、逐字段覆盖与缺失，原始观测按需展开；公告卡显示签发、有效期、限制提示和带行号的固定正文。获取时间、官方入口和技术定位单独提供，在线入口可能更新，固定原文才是这次报告使用的依据。

展示值最多两位小数，原始精度仍保存在固定内容；UTC 时间缩短为可读格式。外部天气数字明确标出来源，不冒充主航班快照或已审核项目指标。[executionPresentation.ts](../../frontend/src/components/executionPresentation.ts) 显示简短真实行动与失败/部分完成摘要，长文和技术记录按需展开。

## 5. 怎么启动和试用

在项目根目录 PowerShell 启动后端：

```powershell
uv run uvicorn metric_pilot.main:app --host 127.0.0.1 --port 8000
```

另开终端启动前端：

```powershell
cd frontend
npm.cmd run dev
```

浏览器打开 **http://127.0.0.1:5173/analysis**。需要本机 `.env` 已配置支持工具调用的模型；模型按实际使用计费，健康检查不发付费请求。

可以这样问：

> 调查本月 ATL 出发航班的取消情况。先比较记录数和取消分布，根据实际结果选择值得核查的日期，再结合天气观测和 FAA 运行公告核对。说明时间、缺测及航司限制，保存发现和简短报告，不直接推断原因。这里只做探索，不冒充已审核项目指标。

然后在同一调查追问：

> 优先复用刚才的固定证据，检查天气覆盖是否完整、公告是否适用于全部航司。保存支持或削弱此前判断的新发现，并说明还有哪些证据不足。

历史天气可能需要读取较大的年度文件，遇到外部超时或覆盖不足时，应能看到真实限制；查不到资料不是证明没有事件。近期天气可问“查 ATL 机场当地昨天的实际观测”，但现有一月航班快照不能用于比较昨天的航班。

## 6. 验证与当前边界

[test_agent_external.py](../../backend/tests/test_agent_external.py) 使用独立 FakeLLM 与明确合成的来源，实际执行工具、SQLite/DuckDB、发现和报告；正式配置没有测试模型入口。覆盖成功调查与续查、失败继续本地核查、越权来源、显式取消、消息配对和累计字节预算。公告部分日期失败另有独立测试。

[verify_external_investigation.py](../../scripts/verify_external_investigation.py) 单独使用真实模型及来源，核对实际报告与发现中的每个 ValueRef；[verify_external_cancellation.py](../../scripts/verify_external_cancellation.py) 以真实 HTTPS 响应体触发取消，观察正式适配器回收传输。浏览器隔离服务使用合成来源，测试与真实来源验收分别记录，不用合成画面冒充真实模型成果。

完整检查、失败修复记录和实际通过项见 [IMPLEMENTATION_STATUS.md](../../IMPLEMENTATION_STATUS.md)。本阶段仍限已登记的三个机场气象站、2026 年映射及 FAA ATCSCC 公开通知；不是全部 NOTAM、任意机场或完整因果调查。未取得批量抓取/公开再分发授权，也未验证长期来源稳定性、跨平台或整体准确率。用户导入属于阶段 6，尚未实施。

## 本轮收尾补充

历史 NCEI 原件可由 Agent 在六小时内经哈希校验后复用，只限超过三十天的历史窗口；页面保留原获取时间并明确缓存，不冒充本轮重新联网。近期 AWC 不缓存；`refresh=true` 可强制重新获取，独立 CLI 默认新联网。新调查仍创建自己的外部版本和成功查询产物，授权边界不变。

上下文超过容量时，先压缩重复 schema、来源摘要和引用 ID；仍超限的已完成批次可以整理为完整“调用—真实回复”配对后裁剪较旧配对，原始批次完整留审计。需要的资料仍可通过工具再读。多列统计优先直接展示整体聚合表，文字解释范围和限制，减少重复改写数量。

此次新调查与续查分别核对 45、32 个引用值；原件缓存、真实联网、合成浏览器和人工抽样分别记录。模型仍可能误解数量、来源或发现类型，引用可解析不是结论正确率；使用时仍需点击依据核对。没有自动批准实际指标、发布 Wiki 或开始阶段 6。

## 天气反馈修复后的行为

天气取得原件后，数据库改为有界批量写入，冻结提交前仍检查取消和超时。工具失败留下的临时版本不会进入成功资料清单，后续调查也不能将它当作成功证据；旧报告保留历史内容，新报告使用新核验的版本。失败展示会区分“请求未完成”“尚未查询”和“成功查询后确实缺测”，机场当地日期不改贴成 UTC。

历史年度文件较大。六小时内可直接校验哈希复用完整原件；过期后先联网用原 ETag 向官方核验，实际 HTTP 304 确认未变才复用，获取时间仍显示原时间，另保留本次核验。来源变化返回200时正常读取新文件。只有截断/失败文件、没有原件或明确 `refresh=true` 时不能走这条捷径，慢网络仍可能超时，系统不会假报成功。近期 AWC 仍不缓存。

这次原失败天气步骤通过真实联网、模型、SQL、发现和报告定向验收，55 个数值引用逐项核对；不代表完整月度航班/公告问题或整体准确率都已重新验收。具体通过与未通过项见实施记录末尾。
